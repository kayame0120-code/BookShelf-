# 要件シートチェックリスト検品（機能要件F列 完了条件 ＋ テスト要件G列 検証観点）

## 採用したチェックリストの所在（シート名・列）
要件シート.xlsx（`docs/00_正本/片倉_菖さん_新模擬案件_Bookshelf_要件シート (1).xlsx`）を python3(zipfile+ElementTree) で inline string 形式のまま、シート名・行・列アドレス付きで全シート抽出した（sharedStrings.xml は無く全て inline string）。抽出した13シートのうち「チェックリスト」に該当する列として以下を採用した。

1. **シート7 機能要件 / F列「完了条件」**（C5=画面名, D5=操作, E5=URL/メソッド, F5=完了条件, G5=基本/応用, H5=成功時の遷移先, I5=確定フラッシュ文言, J5=失敗時の挙動, K5=認可失敗時の挙動, L5=削除済み時の分岐）。F列が「どの画面で何をしたらどうなるか」の完了条件を1行ずつ列挙したチェックリスト本体。付随して H/I/J/K/L 列（遷移先・文言・失敗挙動・認可）も同一行の完了判定材料として突き合わせた。
2. **シート10 テスト要件 / G列「検証観点」**（D11=テスト種別, E11=カテゴリ, F11=基本/応用, G11=検証観点）＋ 全体要件 D5〜D8（通過・カバレッジ・Http::fake()）。G12〜G21 が各機能で確認すべき観点のチェックリスト。G22〜G31（応用カテゴリ）はシート側が観点欄空欄。

シート8（バリデーション）・シート9（シーディング）・シート11（データ要件）・シート12（テーブル仕様）・シート13（API仕様）は完了条件の裏付けとして参照した。シート6（デザインUI画像）は画像本体照合が必要なため対象外（「未確認・保留」に記載）。

## やったこと（事実のみ）
- 要件シート.xlsx をシート名・セルアドレス付きで全抽出し、チェックリスト列（シート7 F列＝完了条件、シート10 G列＝検証観点）を特定した。
- チェックリストの各項目に対応する実装（routes/、app/Http/Controllers/、app/Http/Requests/、app/Policies/、app/Models/、app/Enums/、app/Console/、app/Notifications/、app/Http/Resources/、resources/views/、database/migrations/、database/seeders/、lang/、tests/）を grep/Read で特定し該当行を引用した。
- 第1〜3弾の証拠（`_ズレ調査.md`／`_第2弾.md`／`_第3弾.md`、ズレ計20件）の結論を該当項目に紐付けた（既出は「第N弾ズレM参照」）。
- 実装コード・テストは一切編集していない（Read/Grep/Bash と本 docs/04 ファイルの Write のみ）。

## 2. テストを書かない未カバー行（除外）＝1行ずつ理由付き

`sail artisan test --coverage-clover` で残った app/ 配下の未カバー行は以下がすべて（計13文）。リストに載っていない未カバー行は存在しない（§3で確認）。

| # | ファイル:行 | コード | 除外理由 |
|---|---|---|---|
| 1 | app/Http/Middleware/TrustHosts.php:16-18 | `hosts()` が信頼ホストパターンを返す | フレームワークが自動生成する標準ミドルウェア。Kernel の `$middleware` で有効化されておらず、どのルートの処理経路にも載らない。CLAUDE.md §16「標準生成物を使わない理由だけで削除しない」に従い定義は残置。到達不能のため除外。 |
| 2 | app/Providers/BroadcastServiceProvider.php:15,17 | `Broadcast::routes()` / `require routes/channels.php` | フレームワーク標準のブロードキャスト初期化。本アプリはブロードキャスト機能を使用せず、`config/app.php` のプロバイダ登録経由でしか実行されない到達不能コード。CLAUDE.md §16 に従い残置。除外。 |
| 3 | app/Providers/FortifyServiceProvider.php:31,35 | `return view('auth.login')` / `return view('auth.register')` | 走行①（基本認証）のログイン／登録画面の描画クロージャ。発注書§0 やらないこと#2「基本機能（走行①〜⑥）のテストの作成」に該当し、本走行⑭のスコープ外（基本テストは走行⑥の担当）。ゲストの GET /login・/register 描画を新規にテストすると§0 違反となるため、走行⑭では除外。 |
| 4 | app/Exceptions/Handler.php:66,67 | `TokenMismatchException` 用 renderable の `if (! api/*) return errors.419 view` | Laravel は `Handler::prepareException()` で `TokenMismatchException` を `HttpException(419)` へ**変換してから** renderable を型照合する。変換後は型が `HttpException` になり、この `TokenMismatchException` 型ヒットの renderable には到達しない（=実質デッドコード）。419 の日本語ページ自体はフレームワーク標準の `errors.419` ビュー解決で描画され、`tests/Feature/WebErrorPageTest::test_web_419_returns_japanese_page` で 419＋文言「セッションの有効期限が切れました」を確認済み。当該行は走行⑮の確定済み実装であり本走行のスコープ外・到達不能のため除外。 |
| 5 | app/Console/Commands/ExpireReadingPlans.php:40,41 | `catch (\Throwable $e) { Log::error(...); }` | 失効バッチのレコード単位の防御的例外ログ。正常な業務データ（Enumの有効値で `status` を更新するだけ）では到達しない。強制的に到達させるにはフレームワーク内部で更新処理を失敗注入する必要があり、アプリの振る舞いではなくフレームワークをテストすることになる。バッチ本体の業務分岐（3日前ちょうど失効・境界）は検品表 J で全網羅済み。到達不能の防御ログのため除外。 |
| 6 | app/Console/Commands/SendReadingPlanReminders.php:60,61 | `catch (\Throwable $e) { Log::error(...); }` | リマインダーバッチのレコード単位の防御的例外ログ。#5 と同様、正常データでは到達せず、強制到達には book_id を FK 制約に反して欠損させる等の異常注入が必要（cascade により通常は orphan 計画が作れない）。バッチ本体の業務分岐（timing 別対象 status・in_progress＋expired・二重シナリオ）は検品表 K で全網羅済み。到達不能の防御ログのため除外。 |

### 補足（#4〜#6 は「フレームワーク自動生成/到達不能」枠に該当）
- #4 はフレームワークの例外変換により型照合に到達しない（到達不能）。
- #5・#6 はレコード単位のバッチ継続のための防御的 try/catch であり、正常系・異常系いずれの業務条件でも到達しない防御ログ。強制到達はフレームワーク層の失敗注入テストになり「アプリが使う機能」のテストにならない。
- いずれも実装コード（app/）は本走行で変更していない（テスト追加のみ）。

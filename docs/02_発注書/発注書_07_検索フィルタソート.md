## 1. パラメータの扱い方針（重要な設計判断）

`keyword`・`genre`・`sort`・`page`の4パラメータは、**FormRequestによる422バリデーションを一切設けない**。理由は以下の通り、要件シートの完了条件そのものが「不正な値でもエラーにしない」と明記されているため。

- シート7 R16: キーワード該当0件でも一覧画面自体を表示し「書籍が見つかりませんでした。」と表示する（エラー扱いにしない）
- シート7 R17: ジャンル該当0件でも一覧画面自体を表示する
- シート7 R18: `sort`に未定義の値が渡された場合は`newest`扱いにフォールバックする
- シート7 R19・シート10 R22: 存在しないページ番号でも404にならず空の一覧を表示する（Laravel標準のページネータ動作に従う）

したがって、バリデーションクラスは作成せず、コントローラー内で次の方針により値を安全に既定値へ倒す。

- `keyword`: `request()->string('keyword')->trim()`で取得。空文字なら検索条件に加えない。
- `genre`: `request()->integer('genre')`で取得。0または未指定なら検索条件に加えない。存在しないジャンルIDが渡された場合はバリデーションエラーにせず、`whereHas`が自然に0件を返す挙動に委ねる（この挙動が「該当0件でも一覧画面自体は表示」を自動的に満たす）。
- `sort`: `match`式で`newest` / `oldest` / `title` / `rating`の4値のみ分岐し、それ以外（未指定・未定義値）はすべて`newest`扱いにする。
- `page`: 何もしない。Laravelの`paginate()`が標準で処理する。

## 2. クエリ構築の具体的な実装手順

`BookController@index`内で、以下の順序でクエリビルダを組み立てる。

```php
$query = Book::query();

$keyword = trim((string) $request->query('keyword', ''));
if ($keyword !== '') {
    $query->where(function ($q) use ($keyword) {
        $q->where('title', 'like', "%{$keyword}%")
          ->orWhere('author', 'like', "%{$keyword}%");
    });
}

$genre = (int) $request->query('genre', 0);
if ($genre > 0) {
    $query->whereHas('genres', function ($q) use ($genre) {
        $q->where('genres.id', $genre);
    });
}

$sort = (string) $request->query('sort', 'newest');
match ($sort) {
    'oldest' => $query->orderBy('created_at'),
    'title'  => $query->orderBy('title'),
    'rating' => $query->withAvg('reviews', 'rating')->orderByDesc('reviews_avg_rating'),
    default  => $query->orderByDesc('created_at'), // newest、および未定義値のフォールバック先
};

$books = $query->paginate(10)->withQueryString();

return view('books.index', [
    'books'  => $books,
    'genres' => Genre::all(),
]);
```

**重要（Bladeモック実測で判明した必須事項）**: `books/index.blade.php`のジャンルフィルタ用セレクトは`$genres`という変数（全ジャンルの一覧）を前提に`@foreach($genres ?? [] as $genre)`で選択肢を描画している。`genres`をビューへ渡し忘れると、フォーム自体は表示されるが選択肢が1件も出ず、ジャンルフィルタが実質使用不能になる（`?? []`があるため500エラーにはならず、検品で見た目上気づきにくい穴になる点に注意）。順序の指定はモック・要件シートともに無いため`Genre::all()`でよい。

補足:

- `where`のキーワード条件は必ず1つの無名関数（クロージャ）でグループ化すること。グループ化しないと`orWhere('author', ...)`が`genre`の絞り込み条件までORで巻き込み、「条件の併用（AND）」（シート10 R22）が壊れる。
- `withQueryString()`はLaravel標準のページネータメソッドで、現在のクエリパラメータをそのままページネーションリンクへ引き継ぐ。これにより「ページ送りでの条件維持」（シート10 R22・R23）が実装できる。`appends(request()->query())`と等価だが、こちらのメソッド名を使用すること（可読性のため）。
- `sort=rating`の並び替えはレビュー平均値の高い順（`orderByDesc`）だが、レビューが1件もない書籍は`reviews_avg_rating`が`NULL`になる。MySQLは`DESC`指定時に`NULL`を最後に並べる仕様のため、追加のNULL処理コードは書かないこと（`COALESCE`等で0点扱いに変換すると、0点レビューが付いた書籍と区別できなくなり要件を壊す）。
- ジャンル絞り込みの`genre`はジャンルIDを想定する（`genres.id`）。ジャンル名ではない。書籍登録画面のジャンル選択（`genres[]`、既存実装）と同じくID運用に統一するため。

## 3. 検索結果件数表示・リセットリンクとの連携

- 「検索結果: N件」の表示条件（`keyword`または`genre`のいずれかが指定されている場合のみ表示）は、Blade側が`request()->filled('keyword')`等で判定する実装が既に入っている。コントローラー側は`$books`（ページネータ）と`request()`が通常通りビューから参照できる状態を保てばよく、追加の変数受け渡しは不要。
- リセットリンクは`route('books.index')`への無条件リンクとしてBlade側に実装済み。バックエンド側の対応は不要。

---

## 4. 削除済み書籍・認可

- `Book`モデルは既にSoftDeletesを使用している（走行②で導入済み）。`Book::query()`は標準で論理削除済みレコードを除外するため、追加のコードは不要。「削除済み書籍の除外」（シート10 R22）はこの標準挙動で満たされる。
- `/`・`/books`はゲストもアクセス可能な公開ページであり、認可の概念は発生しない（既存のまま変更なし）。

## 5. 実装上の注意（CC向け）

- 既存の`index`メソッドの並び順が`created_at`降順（newest相当）になっていない場合は、この発注書のデフォルト（`newest`）に統一すること。既存のテストを壊す場合は`QUESTIONS.md`へ記録して停止する。
- `sort`セレクトの選択状態保持（選んだ値が`selected`になる）はBlade側の実装（`request('sort', 'newest')`と比較する形）に既に含まれている。バックエンドが`sort`をそのままクエリパラメータとして残す（`withQueryString()`）以外の対応は不要。
- `genre`が数値化できない文字列（例: `genre=abc`）で渡された場合、`(int) 'abc'`は`0`になりPHPの標準的なキャスト挙動でエラーにならない。この挙動を利用し、明示的な例外処理は書かないこと。

## 0. スコープ

### やること

1. Web（HTML）リクエストで発生する例外を、Laravelの生エラー画面ではなくアプリケーション独自の日本語エラーページで応答させる。対象は 403・404・419・500・503 の5種。
2. `resources/views/errors/` ディレクトリを新規作成し、上記5種の日本語エラーページBladeを配置する。
3. `app/Exceptions/Handler.php` に、Web（HTML）リクエスト向けの例外変換処理を追加する。CSRFトークン不一致（419）の捕捉を含む。

### やらないこと

1. `api/*` リクエスト向けの既存の日本語JSON応答（`Handler.php` の既存 `renderable` 3件）の変更。既に完成しており触らない。
2. 401（未認証）のWeb画面向け変換。未認証でWeb認証必須画面にアクセスした場合は既存のauth/Fortifyミドルウェアが `/login` へリダイレクトする挙動が正であり、エラーページは出さない。
3. バリデーションエラー（422相当）のWeb画面向けエラーページ化。バリデーションエラーは `back()` と `$errors` でフォームに差し戻す既存挙動が正であり、エラーページに飛ばさない。
4. ISBN検索エンドポイント（`BookController::searchByIsbn`）のエラー応答キーの変更。現行実装は既に全4箇所が `message` キーで統一されているため、作業対象は存在しない（§1-4 参照）。
5. フロントエンドJavaScriptの修正。ISBN検索レスポンスを `fetch`／`axios` で受けて `data.error` を参照するJSはリポジトリに存在しないため、作業対象は存在しない（§1-4 参照）。
6. 自動テストコード（PHPUnit）の作成。走行⑭で一括して書く。
7. `resources/views/errors/` 以外の既存Bladeの変更。

## 1. 確定台帳（この走行の全判断）

初読で理解できるよう、この走行で採用する判断をすべてここに確定値として記載する。

### 1-1. 対象例外とHTTPステータスの対応

| 状況 | 例外クラス | ステータス | 応答（Web/HTML） | 応答（API・`api/*`） |
|---|---|---|---|---|
| ページが存在しない | `NotFoundHttpException` | 404 | 日本語エラーページ `errors/404.blade.php` | 既存JSON `{"message":"指定された書籍が見つかりません。"}`（維持） |
| 権限がない | `AccessDeniedHttpException` | 403 | 日本語エラーページ `errors/403.blade.php` | 既存JSON `{"message":"この操作を実行する権限がありません。"}`（維持） |
| CSRFトークン不一致 | `TokenMismatchException` | 419 | 日本語エラーページ `errors/419.blade.php` | APIはSanctumトークン認証でありCSRF検証対象外（該当しない） |
| サーバー内部エラー | 上記以外の `Throwable` | 500 | 日本語エラーページ `errors/500.blade.php`（`APP_DEBUG=false` 時のみ） | Laravel標準（維持） |
| メンテナンス中 | `MaintenanceModeException` | 503 | 日本語エラーページ `errors/503.blade.php` | Laravel標準（維持） |

### 1-2. Web/APIの判定方法

`$request->is('api/*')` が真ならAPIリクエスト（既存JSON応答を維持）、偽ならWebリクエスト（本走行で追加する日本語エラーページを返す）。既存の3つの `renderable` は `api/*` 真の条件下でのみJSONを返し、偽なら何も返さず後続に流す構造になっている。本走行で追加するWeb向け `renderable` は `api/*` 偽の条件下でのみビューを返す。両者は条件が排他であり互いに干渉しない。

### 1-3. 500・503・419の実現方式

- **500**：`APP_DEBUG=true`（開発環境）ではLaravel標準の詳細エラー画面を表示し、`APP_DEBUG=false`（本番・採点者環境）でのみ `errors/500.blade.php` を表示する。Laravelは `APP_DEBUG` の値に応じて500表示を自動で切り替える標準機構を持ち、`errors/500.blade.php` を配置すれば `APP_DEBUG=false` 時に自動でこのビューが使われる。したがって `Handler.php` に500専用の独自分岐は書かず、ビュー配置のみで対応する。
- **503**：`errors/503.blade.php` を配置する。Laravelはメンテナンスモード時にこのビューを自動で使う。`Handler.php` に独自分岐は書かない。
- **419**：`TokenMismatchException` はLaravel標準ではこのビューを自動採用しないため、`Handler.php` の `renderable` で明示的に捕捉して `errors/419.blade.php` を返す（§2-2）。ログイン画面への自動リダイレクトは行わない。

### 1-4. 現行実装で既に完了している事項（作業不要の確認）

実装計画（`実装計画_15_エラー画面日本語化.md`）の現物採取により、以下は既に実装済みであり本走行の作業対象外とする。

- **ISBN検索のエラー応答キー**：`BookController::searchByIsbn` の4箇所（422・502・502・404）はすべて `message` キーで実装済み。`error` キーは残っていない。統一作業は不要。
- **フロントエンドJS**：`data.error` を参照するJavaScriptはリポジトリに存在しない。ISBN検索エンドポイントを `fetch`／`axios` で呼ぶJSも存在しない（`resources/js/app.js` はAlpine初期化のみ）。修正対象が実在しないため作業不要。

### 1-5. エラーページの日本語文言（確定値）

各エラーページに以下の見出し・本文を確定値として置く。専門用語（ステータスコード番号・例外名）を本文に露出させず、ユーザーが次に取るべき行動（前の画面へ戻る／トップへ）を必ず含める。

| ファイル | 見出し | 本文 |
|---|---|---|
| `errors/403.blade.php` | このページにアクセスする権限がありません | お探しのページを表示する権限がありません。トップページからやり直してください。 |
| `errors/404.blade.php` | ページが見つかりません | お探しのページは存在しないか、移動または削除された可能性があります。 |
| `errors/419.blade.php` | セッションの有効期限が切れました | お手数ですが、前の画面に戻ってもう一度お試しください。 |
| `errors/500.blade.php` | エラーが発生しました | 申し訳ありません。サーバーで問題が発生しました。時間をおいて再度お試しください。 |
| `errors/503.blade.php` | ただいまメンテナンス中です | 申し訳ありません。現在メンテナンスを行っています。しばらくお待ちください。 |

### 1-6. エラーページのレイアウト方針（確定値）

現行リポジトリの共通レイアウトは `resources/views/components/app-layout.blade.php` であり、これは内部で `@include('layouts.navigation')` を呼ぶ。`navigation` は `Auth::user()->unreadNotifications` 等のAuth・DB依存処理を含む。エラーページはアプリの状態が不安定な場面（500・503・419）で表示されるため、Auth・DB・未読通知取得に依存する部品を描画すると二次エラーを起こす。したがってエラーページは共通レイアウトを継承せず、各ファイルを独立した完結HTMLとして組む。各ファイルに含めるのは、見出し・本文・トップページ（`route('books.index')`）へのリンクのみとし、Auth・DBクエリ・未読通知取得を一切呼ばない。

## 2. 実装手順

### 2-1. errorsビューの配置

`resources/views/errors/` を作成し、403・404・419・500・503 の5ファイルを配置する。各ファイルは §1-5 の見出し・本文を表示し、§1-6 の通り独立HTMLとする。スタイルは既存モックのTailwindCSSのトーンに合わせ、中央寄せの1カラムとする。CSSは `@vite(['resources/css/app.css'])` を読み込んでよい（これはビルド済みCSSの静的読み込みでありAuth・DB依存を持たない）。

### 2-2. Handler への Web 向け例外変換の追加

`app/Exceptions/Handler.php` の `register()` メソッド内、既存の `api/*` 向け `renderable` 3件の後に、Web向けの `renderable` を追加する。既存3件は変更しない。追加するのは以下3つ。

- `NotFoundHttpException`：`$request->is('api/*')` が偽なら `response()->view('errors.404', [], 404)` を返す。
- `AccessDeniedHttpException`：`$request->is('api/*')` が偽なら `response()->view('errors.403', [], 403)` を返す。
- `TokenMismatchException`：`$request->is('api/*')` が偽なら `response()->view('errors.419', [], 419)` を返す。`use Illuminate\Session\TokenMismatchException;` を追加する（現行の use 文には未追加）。

500・503は §1-3 の通りビュー配置のみで対応し、`Handler.php` に分岐を追加しない。

## 3. 参考実装（literalではなく方針）

`Handler.php` のWeb向け追加分の構造を示す。use文・既存コードとの整合はCCが現物に合わせる。

```php
// use 文に追加
use Illuminate\Session\TokenMismatchException;

// register() 内、既存の api/* 向け renderable 3件の後に追加

$this->renderable(function (NotFoundHttpException $e, Request $request) {
    if (! $request->is('api/*')) {
        return response()->view('errors.404', [], 404);
    }
});

$this->renderable(function (AccessDeniedHttpException $e, Request $request) {
    if (! $request->is('api/*')) {
        return response()->view('errors.403', [], 403);
    }
});

$this->renderable(function (TokenMismatchException $e, Request $request) {
    if (! $request->is('api/*')) {
        return response()->view('errors.419', [], 419);
    }
});
```

## 4. 禁止事項

1. `api/*` 向けの既存 `renderable` 3件を変更しない。
2. `resources/views/errors/` 配下以外の既存Bladeを変更しない。
3. 500・503用に `Handler.php` へ独自の分岐ロジックを追加しない（ビュー配置のみで対応する）。
4. エラーページ内でAuth・DB接続・未読通知件数取得などの動的処理を呼ばない。共通レイアウト（`components/app-layout.blade.php`）を継承しない。
5. `BookController::searchByIsbn` のエラー応答キーを変更しない（既に `message` で統一済み）。
6. 本発注書に明記されていないロジックを独自に追加しない。
7. `main` ブランチへ直接コミットしない。

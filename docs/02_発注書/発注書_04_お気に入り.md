## 1. 前提

着手の前に、次が存在することを現物で確かめる。

| 前提 | 確かめる対象 |
|---|---|
| `favorites` テーブル（`user_id`・`book_id` の複合主キー）がある | `SHOW CREATE TABLE favorites`（テーブルの構造は 11 データの担当） |
| 書籍詳細に、お気に入りボタン（削除されていない書籍のときだけ出る）がある | `resources/views/books/show.blade.php`（01 書籍の持ち物） |

## 2. 担当するルートと画面

### ルート

すべてログイン必須（`auth` を付ける）。

| No | メソッド | URI | ルート名 | 処理 |
|---|---|---|---|---|
| 018 | POST | `/books/{book}/favorites` | favorites.toggle | `App\Http\Controllers\FavoriteController@toggle` |
| 021 | GET | `/favorites` | favorites.index | `App\Http\Controllers\FavoriteController@index` |

- `POST /books/{book}/favorites` は削除済みの書籍を探さない。削除済みの書籍のIDでは404になる
- `routes/web.php` のうち、この表の2本の行だけを担当する

## 4. 作るもの

### 4-1. 切り替え

| 項目 | 確定値 |
|---|---|
| 入口 | 書籍詳細のお気に入りボタン。未登録なら「お気に入りに追加」、登録済みなら「お気に入りから削除」。未ログインのときはログイン画面へのリンク。お気に入り一覧の各書籍のボタンからも呼ぶ |
| 動き | 押すたびに、（ログイン中の会員・その書籍）の `favorites` の行を登録・解除で切り替える |
| 押した後 | 元の画面（書籍詳細から押したら書籍詳細、お気に入り一覧から押したらお気に入り一覧）に戻る |
| メッセージ | 出さない。状態はボタンの文字で表す（お気に入り一覧の Blade にメッセージを出す欄が無く、同じ操作を2つの画面から呼ぶため、片方だけメッセージが出る状態を避ける） |
| 削除済みの書籍 | 404 |

書籍が削除されても `favorites` の行は残す（論理削除のため外部キーの cascade は働かない）。

### 4-2. お気に入り一覧（PG10）

| 項目 | 確定値 |
|---|---|
| 対象 | ログイン中の会員のお気に入りだけ。削除済みの書籍を除く |
| 並び | 書籍の登録が新しい順（お気に入りに登録した順ではない） |
| 件数 | 1ページ10件 |
| 各書籍のカード | カード全体を書籍詳細 `/books/{book}` へのリンクにし、お気に入りボタンだけを前面で押せるようにする |
| 画像が無いとき | 「No Image」 |
| ISBN が無いとき | 「未登録」と出さない。「ISBN: 」の後ろが空になる |
| 0件のとき | 「お気に入りに登録された書籍はありません。」と、書籍一覧へのリンク「書籍一覧を見る」 |

### 4-3. 提供モックから変える箇所

`resources/views/favorites/index.blade.php` に次の変更を加える。ここに無い変更をしない。

| 変えること |
|---|
| カード全体を書籍詳細へのリンクにし、お気に入りボタンだけを前面で押せるようにする |
| ISBN が無いときの「未登録」の表示を削除する |

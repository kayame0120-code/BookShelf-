# 発注書 11 データ

全テーブルの構造（カラムの型・NULL の可否・主キー・外部キーと削除時の挙動）、テーブル間の関係、初期データ、ジャンル削除を止めるDB側の制約を担当する。ルート・画面は持たない。

テーブルはテーブル名とカラム名で書く。マイグレーションのファイル名では書かない。

- 合格の基準: `docs/03_検品表/11_データ.md`（この番号の全条件を1条件1行で並べた表）。この発注書に書かれていても検品表に無い作業は完成条件に含まれない
- 共通の規則: `docs/共通ルール.md` の1章（着手前の確認・書かれていないことをしない・定義が無い場面での止まり方・変更してよい範囲・コミット・完了報告）と3章（文書の書き方）

## 1. 前提

| 前提 | 確かめる対象 |
|---|---|
| MySQL 8.4 が Sail で動いている | `sail exec mysql mysql --version` |
| Laravel Sanctum が入っている（`personal_access_tokens` のテーブル作成を持つ） | `composer show laravel/sanctum` |

## 2. 対象ファイル（この番号が持つファイル。変更してよいのは「担当する部分」の範囲）

| 対象 | 担当する部分 |
|---|---|
| `database/migrations/` | 全体 |

## 3. 作るもの

### 3-1. テーブル（13個・78カラム）

文字コードは全テーブル utf8mb4 ／ utf8mb4_unicode_ci。

| テーブル | 役割 | モデル | 論理削除 |
|---|---|---|---|
| users | 会員 | `App\Models\User` | なし |
| genres | ジャンル | `App\Models\Genre` | なし |
| books | 書籍 | `App\Models\Book` | あり（`deleted_at`） |
| book_genre | 書籍とジャンルの紐付け | なし（中間テーブル） | なし |
| reviews | レビュー | `App\Models\Review` | なし |
| favorites | お気に入り | なし（中間テーブル） | なし |
| review_likes | いいね | なし（中間テーブル） | なし |
| reading_plans | 読書計画 | `App\Models\ReadingPlan` | なし |
| notifications | 通知（Laravel 標準の形式） | なし（`DatabaseNotification` を使う） | なし |
| personal_access_tokens | APIトークン（Sanctum 標準） | なし | なし |
| password_reset_tokens | パスワード再設定（Laravel 標準。機能は無効） | なし | なし |
| failed_jobs | 失敗したキュー処理（Laravel 標準・未使用） | なし | なし |
| migrations | テーブル作成の実行記録（Laravel 標準） | なし | なし |

各カラムの型・NULL の可否・初期値・キーは、全体仕様書 11章の表のとおりにする。主なものは次のとおり。

| テーブル | カラム | 型 | NULL | キー |
|---|---|---|---|---|
| users | email | varchar(255) | 不可 | 一意 |
| genres | name | varchar(255) | 不可 | 一意 |
| books | isbn | varchar(13) | **可** | 一意 |
| books | published_date | date | **可** | — |
| books | deleted_at | timestamp | 可 | — |
| book_genre | book_id・genre_id | bigint unsigned | 不可 | 2つで主キー |
| reviews | rating | tinyint unsigned | 不可 | — |
| reviews | comment | text | 可 | — |
| favorites | user_id・book_id | bigint unsigned | 不可 | 2つで主キー |
| review_likes | user_id・review_id | bigint unsigned | 不可 | 2つで主キー |
| reading_plans | target_date | date | 不可 | — |
| reading_plans | status | varchar(20) | 不可 | — |
| reading_plans | completed_at | timestamp | 可 | — |

`books.isbn`・`books.published_date` を NULL 可にするのは、画面の書籍登録で ISBN と出版日を任意にするため（公開APIでは必須のまま。入力チェックで止める）。

### 3-2. 外部キーと削除時の挙動（11本）

| テーブル | カラム | 参照先 | 削除時 |
|---|---|---|---|
| books | user_id | users.id | restrict（削除を拒否） |
| book_genre | book_id | books.id | cascade（連動削除） |
| book_genre | genre_id | genres.id | restrict |
| reviews | user_id | users.id | restrict |
| reviews | book_id | books.id | cascade |
| favorites | user_id | users.id | restrict |
| favorites | book_id | books.id | cascade |
| review_likes | user_id | users.id | restrict |
| review_likes | review_id | reviews.id | cascade |
| reading_plans | user_id | users.id | restrict |
| reading_plans | book_id | books.id | cascade |

- `notifications` は `notifiable_type`・`notifiable_id`、`personal_access_tokens` は `tokenable_type`・`tokenable_id` で会員を指し、外部キーを持たない
- `book_genre.genre_id` の restrict が、ジャンル削除を止めるDB側の制約である。アプリ側の確認（02 ジャンルの担当）と二重の防御になる
- books は論理削除のため、削除しても cascade は働かず、紐づくレビュー・お気に入り・紐付け・読書計画は残る。cascade が働くのは物理削除の場合だけで、アプリに物理削除の処理を作らない
- 会員を削除する処理は無い

### 3-3. 初期データ

`sail artisan migrate:fresh --seed` で、毎回次の状態を作る。

**毎回同じ部分**（件数と中身が、何度投入しても変わらない）

| テーブル | 件数 |
|---|---|
| users | 5 |
| genres | 10 |
| books | 11 |
| book_genre | 16 |
| favorites | 19 |
| reading_plans | 6 |
| notifications | 0 |
| personal_access_tokens | 0 |
| password_reset_tokens | 0 |
| failed_jobs | 0 |
| migrations | 14 |

**実行のたびに変わる部分**

| テーブル | 決め方 |
|---|---|
| reviews | 投稿者・件数・評価を乱数で決める（`Database\Seeders\ReviewSeeder@run`）。評価は1〜5 |
| review_likes | レビューに連動して変わる |

書籍の登録者も乱数で決める（`Database\Seeders\BookSeeder@run`）。初期データを乱数にするのは、マイ読書レポートで複数の会員と評価の分布を見せるため（応用要件）。

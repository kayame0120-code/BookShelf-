# 発注書 00 共通動作

全機能に共通する動きと、それを起こしている部品、エラー画面、ヘッダーの構造、ルートを持たない画面部品、入力チェックの標準文言、アプリが変更していない標準ファイルを担当する。この番号はルートも画面（PG）も持たない。

- 合格の基準: `docs/03_検品表/00_共通動作.md`（この番号の全条件を1条件1行で並べた表）。この発注書に書かれていても検品表に無い作業は完成条件に含まれない
- 共通の規則: `docs/共通ルール.md` の1章（着手前の確認・書かれていないことをしない・定義が無い場面での止まり方・変更してよい範囲・コミット・完了報告）と3章（文書の書き方）
- 提供モック・要件シート: 学校から配布された資料。提供モックは画面のひな形（Blade）、要件シートは作るものを定めた表で、所在と、実装との関係は `docs/00_提供資料/提供資料の所在.md` にある
- 材料: 機能仕様書 0章（全機能に共通する動き）、全体仕様書 3章（画面一覧・エラー画面・画面部品）・4章（ルート52本の一覧）・5章（権限一覧）、技術決定書 TD-01（画面遷移）・TD-02（フラッシュ）・TD-20（エラー画面）・TD-22（提供モックから変えたファイル）・TD-26（英語の項目名が出る挙動）

## 3. 作るもの

### 3-1. 未ログイン時の誘導

| 項目 | 確定値 |
|---|---|
| 誘導を行う部品 | `App\Http\Middleware\Authenticate@redirectTo`。画面のリクエストのとき、ルート名 `login`（`GET /login`）を返す |
| 部品の登録 | `App\Http\Kernel` の別名 `auth` を `App\Http\Middleware\Authenticate` に結び付ける |
| ログイン後の戻り先 | 最初に開こうとした画面（Laravel 標準の戻り先の記録を使う） |

ログイン必須をかけるルートは、各番号が自分の担当ルートの行で `auth` を付けて決める。結果として次の31本が `App\Http\Middleware\Authenticate` を通る状態にする（全体仕様書 4章でログインが「必須」の画面のルート）。

| 担当 | ルート |
|---|---|
| 01 書籍 | `POST /books`・`GET /books/create`・`GET /books/isbn/{isbn}`・`PUT /books/{book}`・`DELETE /books/{book}`・`GET /books/{book}/edit`・`PATCH /books/{book}/restore` |
| 02 ジャンル | `GET /genres`・`POST /genres`・`GET /genres/create`・`GET /genres/{genre}`・`PUT・PATCH /genres/{genre}`・`DELETE /genres/{genre}`・`GET /genres/{genre}/edit` |
| 03 レビュー・いいね | `POST /books/{book}/reviews`・`PUT /reviews/{review}`・`DELETE /reviews/{review}`・`GET /reviews/{review}/edit`・`POST /reviews/{review}/like` |
| 04 お気に入り | `POST /books/{book}/favorites`・`GET /favorites` |
| 08 読書計画 | `GET /reading-plans`・`POST /reading-plans`・`GET /reading-plans/create`・`PUT /reading-plans/{plan}`・`DELETE /reading-plans/{plan}`・`POST /reading-plans/{plan}/complete`・`GET /reading-plans/{plan}/edit` |
| 09 通知 | `GET /notifications`・`POST /notifications/{notification}/read` |
| 10 マイ読書レポート | `GET /reports` |

ログインが不要な `GET /`・`GET /books`・`GET /books/{book}`・`GET /ranking` には `auth` を付けない。

### 3-2. トークン検証（CSRF）

| 項目 | 確定値 |
|---|---|
| 検証を行う部品 | `App\Http\Middleware\VerifyCsrfToken` |
| 登録 | `App\Http\Kernel` の `web` グループに入れる |
| 不一致のとき | 419。画面は 3-4 の `errors/419.blade.php` |

トークン検証はログインの確認より先に働く。そのため、トークンを付けずに外から送った書き込みは、未ログインであってもログイン画面へ移らずに419になる。これは Laravel 標準の順序であり、変えない。

### 3-3. 権限判定クラスの登録

`App\Providers\AuthServiceProvider` に、モデルと権限判定クラスの対を次の3組で登録する。各クラスの判定の中身は、書籍が 01、レビューが 03、読書計画が 08 の担当。

| モデル | 権限判定クラス |
|---|---|
| `App\Models\Book` | `App\Policies\BookPolicy` |
| `App\Models\Review` | `App\Policies\ReviewPolicy` |
| `App\Models\ReadingPlan` | `App\Policies\ReadingPlanPolicy` |

権限が無いときは403。ジャンルには所有者が無く権限判定クラスを作らない。通知の既読化は権限判定クラスではなく `App\Http\Controllers\NotificationController@read` で確かめる（09 の担当）。

### 3-4. エラー画面

| ステータス | 画面 | 表示される条件 | 描画の仕組み |
|---|---|---|---|
| 403 | `resources/views/errors/403.blade.php` | 権限の無い操作 | `App\Exceptions\Handler@register` で、画面のリクエストのときビュー `errors.403` を返す |
| 404 | `resources/views/errors/404.blade.php` | 存在しないURL・存在しないID | 同上、ビュー `errors.404` |
| 419 | `resources/views/errors/419.blade.php` | CSRFトークンの不一致 | 同上、ビュー `errors.419` |
| 500 | `resources/views/errors/500.blade.php` | サーバー内部エラー | Laravel が `errors/` の Blade を自動で使う |
| 503 | `resources/views/errors/503.blade.php` | メンテナンス中 | 同上 |

- 5枚とも日本語の文言を持つアプリの画面にし、Laravel 標準の英語の画面（`Forbidden`・`Not Found`・`Page Expired`）を出さない
- `/api/*` のときに JSON を返す処理は 07 公開API の担当。この番号は画面を返す分岐だけを持つ

### 3-5. 入力エラー時の戻り方と、成功メッセージの表示規則

| 場面 | 確定値 |
|---|---|
| 画面の入力エラー | 入力画面に戻り、入力値を残したまま各項目の下にエラー文言を出す（FormRequest を使った Laravel 標準の動き） |
| 成功時のメッセージ | 移動先の画面の上部に緑の帯で出す。次の画面を開き直すと消える（1回だけ出る） |
| メッセージの形 | 「〇〇を△△しました」（句点なし） |
| メッセージを出さない操作 | お気に入りの切り替え・いいねの切り替え・通知の既読化・ログイン・会員登録・ログアウト |
| 失敗をメッセージで出す操作 | ジャンルの削除拒否だけ（赤の帯。02 の担当） |

個々の文言と移動先は各番号の発注書にある。

### 3-7. ヘッダーの構造

`resources/views/layouts/navigation.blade.php` は提供モックの内容のまま使う（提供モックから変えたファイルの一覧である技術決定書 TD-22 に載っていない）。

| 状態 | 表示するもの |
|---|---|
| 未ログイン・ログイン中の両方 | 書籍一覧・ランキング・書籍登録・お気に入り・ジャンル管理・マイレポート・読書計画の7本のリンク（未ログインで押すとログイン画面へ） |
| ログイン中だけ | 通知ベル（`/notifications` へのリンク）、ユーザー名のメニュー（`POST /logout` の送信を含む） |
| 未ログインだけ | ログイン・新規登録のリンク |

通知ベルの未読件数（赤丸）の表示とその件数の受け渡しは 09 通知の担当。

### 3-8. ルートを持たない画面部品

| 対象 | 確定値 |
|---|---|
| `resources/views/components/` の15本 | 提供モックの内容のまま。1文字も変えない |

### 3-9. 入力チェックの標準文言（`lang/ja/validation.php`）

各番号が FormRequest で個別の文言を決めていないルールに使う。

| キー | 値 |
|---|---|
| `string` | `:attributeは文字列で入力してください。` |
| `date` | `:attributeは正しい日付形式で入力してください。` |
| `required` | `:attributeは必須です。` |
| `attributes.name` | `名前` |

`attributes` に `target_date` の日本語訳を置かない。読書計画の期日に日付でない値を入れたときは「target dateは正しい日付形式で入力してください。」と英語の項目名のまま出る（技術決定書 TD-26 の現状の挙動）。

### 3-10. フレームワークが標準で置き、アプリが変更していないファイル

次のファイルは、フレームワークが置いた内容のまま変更しない。使わない機能のための定義であっても削除しない。

| 区分 | ファイル |
|---|---|
| ミドルウェア6本 | `App\Http\Middleware\EncryptCookies`・`App\Http\Middleware\PreventRequestsDuringMaintenance`・`App\Http\Middleware\TrimStrings`・`App\Http\Middleware\TrustHosts`・`App\Http\Middleware\TrustProxies`・`App\Http\Middleware\ValidateSignature` |
| プロバイダ3本 | `App\Providers\AppServiceProvider`・`App\Providers\BroadcastServiceProvider`・`App\Providers\EventServiceProvider` |
| 設定12本 | `config/` 直下のファイルのうち、`app.php`・`fortify.php`・`sanctum.php`・`services.php` の4本を除いた12本 |
| ルート定義2本 | `routes/console.php`・`routes/channels.php` |

除いた4本の持ち主: `config/app.php` は `providers` への `App\Providers\FortifyServiceProvider` の登録が 06 会員登録・ログイン、`timezone` が 09 通知。`config/fortify.php` は 06、`config/sanctum.php` は 07 公開API、`config/services.php` は 01 書籍（Google Books API のキーを持つ）。定期処理の登録は `routes/console.php` ではなく `App\Console\Kernel` にある（09 通知の担当）。

### 3-11. アプリが使っていないルート

外部パッケージ（Ignition。エラー画面の開発者向け機能）が自動で登録するルート。どの番号にも属さない。アプリのコード（`app/`・`routes/`・`resources/`・`lang/`・`database/`）から呼ばない。

| No | メソッド | URI | ルート名 |
|---|---|---|---|
| 002 | POST | `/_ignition/execute-solution` | ignition.executeSolution |
| 003 | GET | `/_ignition/health-check` | ignition.healthCheck |
| 004 | POST | `/_ignition/update-config` | ignition.updateConfig |

レビューの投稿・編集・削除と、レビューへのいいねの登録と解除を担当する。

- 合格の基準: `docs/03_検品表/03_レビューいいね.md`（この番号の全条件を1条件1行で並べた表）。この発注書に書かれていても検品表に無い作業は完成条件に含まれない
- 共通の規則: `docs/共通ルール.md` の1章（着手前の確認・書かれていないことをしない・定義が無い場面での止まり方・変更してよい範囲・コミット・完了報告）と3章（文書の書き方）
- 提供モック・要件シート: 学校から配布された資料。提供モックは画面のひな形（Blade）、要件シートは作るものを定めた表で、所在と、実装との関係は `docs/00_提供資料/提供資料の所在.md` にある
- 全機能に共通する動き（未ログイン時の誘導・エラー画面・入力エラー時の戻り方・成功メッセージの表示規則・削除済み書籍の扱いの原則）: `docs/02_発注書/発注書_00_共通動作.md`
- 材料: 機能仕様書 3章（レビュー・いいね）・1-2（書籍詳細のレビュー一覧と投稿フォーム）、全体仕様書 3章（PG09）・4章（ルート一覧）・5章（権限一覧）、技術決定書 TD-01・TD-02・TD-03・TD-04・TD-27

## 1. 前提

着手の前に、次が存在することを現物で確かめる。

| 前提 | 確かめる対象 |
|---|---|
| `reviews` テーブル（`user_id`・`book_id`・`rating`・`comment`）と `review_likes` テーブル（`user_id`・`review_id`） | `SHOW CREATE TABLE reviews`・`SHOW CREATE TABLE review_likes`（テーブルの構造は 11 データの担当） |
| `review_likes.review_id` が `reviews.id` を cascade で参照している | `SHOW CREATE TABLE review_likes` |
| `App\Models\Review::book` が削除済みの書籍も取れる関連である | 00 共通動作の担当 |
| 権限判定クラスの登録 `App\Models\Review` → `App\Policies\ReviewPolicy` | `App\Providers\AuthServiceProvider`（登録は 00 の担当） |
| 書籍詳細 `GET /books/{book}` が削除済みの書籍も表示する | 01 書籍の担当 |

## 2. 担当するルートと画面

### ルート

すべてログイン必須（`auth` を付ける）。

| No | メソッド | URI | ルート名 | 処理 |
|---|---|---|---|---|
| 020 | POST | `/books/{book}/reviews` | reviews.store | `App\Http\Controllers\ReviewController@store` |
| 045 | PUT | `/reviews/{review}` | reviews.update | `App\Http\Controllers\ReviewController@update` |
| 046 | DELETE | `/reviews/{review}` | reviews.destroy | `App\Http\Controllers\ReviewController@destroy` |
| 047 | GET | `/reviews/{review}/edit` | reviews.edit | `App\Http\Controllers\ReviewController@edit` |
| 048 | POST | `/reviews/{review}/like` | reviews.like | `App\Http\Controllers\ReviewController@like` |

- `POST /books/{book}/reviews` は削除済みの書籍を探さない。削除済みの書籍のIDでは404になる

## 4. 作るもの

### 4-1. 投稿

| 項目 | 確定値 |
|---|---|
| 入口 | 書籍詳細の投稿フォーム。削除されていない書籍でログイン中のときだけ出す（未ログイン・削除済みのときの代わりの文言は 01 の担当） |
| 評価の入力 | プルダウン。1つ目が「選択してください」、続いて★1〜★5（値は1〜5） |
| コメントの入力 | placeholder「この書籍の感想を書いてください」 |
| 投稿者 | ログイン中の会員（`reviews.user_id`） |
| 件数の制限 | 置かない。同じ会員が同じ書籍に何件でも投稿できる |
| 成功時 | 書籍詳細へ移動し、「レビューを投稿しました」 |
| 削除済みの書籍 | 404 |

### 4-2. 入力ルール（投稿・更新共通）

投稿は `App\Http\Requests\StoreReviewRequest`、更新は `App\Http\Requests\UpdateReviewRequest` に、ルールと文言を同じクラスに書く。失敗時は入力画面に戻り、レビューを保存しない。

| 項目 | ルール | エラー文言 |
|---|---|---|
| 評価 `rating` | 必須・整数・1〜5 | 「評価を選択してください」「評価は1〜5の範囲で選択してください」 |
| コメント `comment` | 任意・文字列・1000文字以内 | 「コメントは1000文字以内で入力してください」 |

コメントを空で送ったときは `reviews.comment` を NULL で保存する。

### 4-3. 書籍詳細のレビュー一覧

| 項目 | 確定値 |
|---|---|
| 並び | 新しい順 |
| 各レビュー | 評価（★）、投稿日（`Y/m/d`）、コメント（ある場合のみ）、いいねボタンと件数 |
| 投稿者本人にだけ出すもの | 編集画面へのリンク、削除ボタン（確認「本当に削除しますか？」） |
| 書籍が削除済みのとき | すべてのレビューを表示する |
| 0件のとき | 「まだレビューはありません。」 |

### 4-4. 編集（PG09）・更新

| 項目 | 確定値 |
|---|---|
| 権限 | 投稿者本人のみ。本人以外は403 |
| 書籍が削除済みのとき | 編集・更新できる |
| 入力ルール | 4-2 と同じ |
| 成功時 | 書籍詳細へ移動し、「レビューを更新しました」 |

### 4-5. 削除

| 項目 | 確定値 |
|---|---|
| 権限 | 投稿者本人のみ。本人以外は403 |
| 削除の方式 | 物理削除。そのレビューへのいいね（`review_likes`）は外部キーの cascade で連動して消える |
| 書籍が削除済みのとき | 削除できる |
| 成功時 | 書籍詳細へ移動し、「レビューを削除しました」 |

### 4-6. いいね

| 項目 | 確定値 |
|---|---|
| 動き | 押すたびに、（ログイン中の会員・そのレビュー）の `review_likes` の行を登録・解除で切り替える |
| 押せる対象 | 自分のレビューにも押せる。書籍が削除済みのレビューにも押せる |
| 押した後 | 元の画面に戻る。メッセージは出さない |
| ボタンの文字 | 未登録は「いいね (件数)」、登録済みは「いいね済み (件数)」 |

### 4-7. 権限判定（`App\Policies\ReviewPolicy`）

| メソッド | 許可する条件 |
|---|---|
| `update` | レビューの `user_id` がログイン中の会員のIDと同じ |
| `delete` | レビューの `user_id` がログイン中の会員のIDと同じ |

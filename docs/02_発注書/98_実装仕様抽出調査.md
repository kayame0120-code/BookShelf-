# 98 実装仕様抽出調査（調査依頼）

## 1. 目的

実装を正として、全体仕様書・機能仕様書・技術決定書の3本を新規に作るための、実装の事実の全量抽出。
CCの仕事は「実装の一覧から機械的に作った抽出台帳を、実装の事実で全部埋めること」だけ。

- 仕様書の執筆、良し悪しの判定、修正案の作成はCCの仕事ではない（執筆は設計チャット側が行う）
- 抽出の単位は、ルート全件・テーブル全件・Blade全件・定期処理と通知の全ファイル・横断設定の全ファイル。さらに最後に、実装ファイルのうち台帳のどこからも参照されていないものを機械的に洗い出して全部埋める。**単位の選択・間引き・「主要なものだけ」の抽出は禁止**

## 2. 対象

| 項目 | 値 |
|---|---|
| 対象コミット | `03bbdbfd881705c5f30833963840ba1718e6ebdb`（発注書99で調査したコミットと同じ） |
| 成果物の置き場所 | `docs/04_検品結果/仕様抽出/` |
| 参照してよい既存の記録 | `docs/04_検品結果/照合調査/` の 実行結果.md・実装全文.txt（同じコミットで取得済み。台帳では `照合R12` のように書いて参照してよい） |

## 3. 禁止事項

1. 実装ファイル・`docs/` 既存ファイルの変更（成果物フォルダ `docs/04_検品結果/仕様抽出/` への書き込みのみ可）
2. DBを変更するコマンドの実行（`migrate` `db:seed` `db:wipe` ほか、INSERT/UPDATE/DELETE/ALTER/DROP を含むSQL、書き込みを伴う tinker）
3. パッケージの追加・更新
4. `.env` の内容の出力。パスワードをコマンドに直接書くこと
5. commit・push・merge・rebase・reset・ブランチの作成と削除。git操作で許可するのは対象コミットへの `checkout --detach` と、Step4 の元の状態への復帰のみ
6. 台帳の「事実:」欄に判定語を自分の言葉で書くこと（一致／不一致／相違／ズレ／正しい／誤り／問題／OK／YES／NO／PASS／FAIL／合格／準拠／想定通り）。引用に含まれる場合は可
7. 台帳のブロック・F行の削除、並べ替え、F行本文と入口情報（`- 名前:` ほか）の書き換え

## 4. 停止条件（該当したら `QUESTIONS.md` に書いて停止）

1. Step0 開始時点で `git status --short --untracked-files=no` の出力が空でない
2. 対象コミットへの切り替えに失敗する
3. Sail が起動しておらず、`./vendor/bin/sail up -d` でも起動しない

## 5. 手順

作業ディレクトリ: リポジトリルート。記録は `docs/04_検品結果/仕様抽出/実行結果.md` に、コマンドと出力をそのまま貼る（形式は発注書99 §5 と同じ）。

| No | コマンド |
|---|---|

| S01 | `git checkout --detach 03bbdbfd881705c5f30833963840ba1718e6ebdb && git rev-parse HEAD` |

ROUTES, TABLES, OUT = sys.argv[1], sys.argv[2], sys.argv[3]
os.makedirs(OUT, exist_ok=True)
def ls(*paths):
    r = subprocess.run(['git', '-c', 'core.quotepath=off', 'ls-files', '--', *paths], capture_output=True, text=True, check=True)
    return [l for l in r.stdout.splitlines() if l]
def block(bid, title, info, fields):
    b = [f'### {bid} {title}']
    for k, v in info: b.append(f'- {k}: {v}')
    for i, f in enumerate(fields, 1):
        b.append(f'- F{i}: {f}'); b.append('  - 事実: （未記入）')
    return '\n'.join(b)
def write(name, head, blocks):
    body = f'# 抽出台帳 {head}\n\n- 件数: {len(blocks)}\n- 記入規則: docs/02_発注書/98_実装仕様抽出調査.md の §6\n- ブロック・F行の削除、並べ替え、F行本文と「- 」で始まる入口情報の編集は禁止。「事実:」行の記入と追加のみ行う。\n\n---\n\n' + '\n\n'.join(blocks) + '\n'

tables = [l.strip() for l in open(TABLES, encoding='utf-8') if l.strip()]

## 6. 台帳の記入規則

### 6-1. 単位

- F行1つにつき「事実:」を1つ以上書く。1つのF行に当てはまる事実が複数あるとき（リダイレクト先とフラッシュ文言、ルールとメッセージ、失敗の場合ごと）は、1事実1行に分けて追加する
- 最初の「事実: （未記入）」を書き換え、2つ目以降は直下に `  - 事実: ` で始まる行を追加する
- 入力検証のルールとメッセージ、フラッシュ文言、画面の固定文言、通知の文言は、全件を1件ずつ書く（「ほか」「以下同様」でまとめない）

### 6-2. 事実の書き方（次の5形式のどれか）

| 形式 | 書き方 | 例 |
|---|---|---|
| コード | `相対パス:行番号` ＋ その行の抜粋（コピーしたまま）。範囲は `相対パス:開始-終了` | `事実: app/Http/Controllers/BookController.php:52 return redirect()->route('books.show', $book)->with('success', '書籍を登録しました');` |
| 実行 | `Snn`（この調査の記録）または `照合Rnn`（発注書99の記録）＋ 該当する出力行の抜粋 | `事実: 照合R22 302 http://localhost:8022/login` |
| 該当なし | 探したコマンドと、その出力（0件）をそのまま | `事実: 該当なし grep -n "authorize" app/Http/Controllers/RankingController.php → 出力0件` |
| N/A-外部パッケージ | アプリ側に手を加えたコードが1行も無い外部パッケージのルート・機能の場合のみ。探したコマンドと0件の出力を添える | `事実: N/A-外部パッケージ（spatie/laravel-ignition） grep -rn "ignition" app config/app.php → 出力0件` |
| 同上 | 同じ事実の再掲 | `事実: 同上 R012 F5` |

- 認可・入力検証・副作用が「無い」場合も「該当なし」の形式で書く。空欄や「なし」の一言は禁止
- Fortify のような外部パッケージのルートでも、アプリ側で設定・上書きしているコード（`app/Actions` `app/Providers` `config/fortify.php` ほか）があれば、そのコードを事実として書く
- 挙動の良し悪しや、要件・発注書と比べた感想は書かない

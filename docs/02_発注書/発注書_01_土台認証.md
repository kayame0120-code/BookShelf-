#### (f) `app/Actions/Fortify/CreateNewUser.php`

`PasswordValidationRules` トレイトの `use` を外し、ルールを直書きする。`create()` を以下にする。

```php
public function create(array $input)
{
    Validator::make($input, [
        'name' => ['required', 'string', 'max:255'],
        'email' => ['required', 'email', 'max:255', 'unique:users,email'],
        'password' => ['required', 'string', 'min:8', 'confirmed'],
    ], [
        'name.required' => 'お名前を入力してください',
        'name.max' => 'お名前は255文字以内で入力してください',
        'email.required' => 'メールアドレスを入力してください',
        'email.email' => 'メールアドレスの形式が正しくありません',
        'email.max' => 'メールアドレスは255文字以内で入力してください',
        'email.unique' => 'このメールアドレスは既に登録されています',
        'password.required' => 'パスワードを入力してください',
        'password.min' => 'パスワードは8文字以上で入力してください',
        'password.confirmed' => 'パスワード確認が一致しません',
    ])->validate();

    return User::create([
        'name' => $input['name'],
```

#### (a) 標準マイグレーションの調整

#### (b) 新規マイグレーション（下記の順序で `make:migration` する。順序＝FK解決順）

1. `create_genres_table`
2. `create_books_table`
3. `create_reviews_table`
4. `create_book_genre_table`
5. `create_favorites_table`
6. `create_review_likes_table`

**genres**

```php
Schema::create('genres', function (Blueprint $table) {
    $table->id();
    $table->string('name', 255)->unique();
    $table->timestamps();
});
```

**books**

```php
Schema::create('books', function (Blueprint $table) {
    $table->id();
    $table->string('title', 255);
    $table->string('author', 255);
    $table->string('isbn', 13)->unique();
    $table->date('published_date');
    $table->text('description')->nullable();
    $table->string('image_url', 255)->nullable();
    $table->foreignId('user_id')->constrained()->restrictOnDelete();
    $table->softDeletes();
    $table->timestamps();
});
```

`isbn` の UNIQUE は論理削除済みレコードも占有し続ける。これは意図した設計であり、`whereNull('deleted_at')` 付きの部分インデックス等に置き換えないこと（削除連動 土台設計確定書 03「ISBN一意性チェック」）。

**reviews**

```php
Schema::create('reviews', function (Blueprint $table) {
    $table->id();
    $table->foreignId('user_id')->constrained()->restrictOnDelete();
    $table->foreignId('book_id')->constrained()->cascadeOnDelete();
    $table->unsignedTinyInteger('rating');
    $table->text('comment')->nullable();
    $table->timestamps();
});
```

`rating` に CHECK 制約は設けない（1〜5 の範囲検証は走行③の FormRequest 側）。
`book_id` の `cascadeOnDelete()` は books が SoftDelete のため実際には発火しないが、設定は残す（シート12・確定書に明記）。

**book_genre**

```php
Schema::create('book_genre', function (Blueprint $table) {
    $table->foreignId('book_id')->constrained()->cascadeOnDelete();
    $table->foreignId('genre_id')->constrained()->restrictOnDelete();
    $table->primary(['book_id', 'genre_id']);
});
```

**favorites**

```php
Schema::create('favorites', function (Blueprint $table) {
    $table->foreignId('user_id')->constrained()->restrictOnDelete();
    $table->foreignId('book_id')->constrained()->cascadeOnDelete();
    $table->primary(['user_id', 'book_id']);
});
```

**review_likes**

```php
Schema::create('review_likes', function (Blueprint $table) {
    $table->foreignId('user_id')->constrained()->restrictOnDelete();
    $table->foreignId('review_id')->constrained()->cascadeOnDelete();

```

**中間3テーブルに `$table->timestamps()` を付けない。** シート12 の列定義に created_at/updated_at がなく、モデル側でも `withTimestamps()` を使わないため。付けると走行⑤の `sync()` / `syncWithoutDetaching()` と噛み合わない。

- `welcome.blade.php` は `route('login')` `route('register')` のみを参照するため走行①時点でも描画できる（実測）。

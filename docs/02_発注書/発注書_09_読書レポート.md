## 2. `ReportController@index` の実装

### 2-1. 全体方針

- `foreach` のような手続き的なループを使わない。`map` / `filter` / `groupBy` / `flatMap` といったCollectionメソッドを使い、宣言的に実装する（シート3の★Collectionメソッド活用基準。本機能はこの基準を徹底する対象として名指しされている）。
- 全メソッドに引数・戻り値の型宣言を行う（例: `public function index(): View`）。
- 主要メソッドにPHPDocを付与する。
- 集計対象は常にログインユーザー自身のデータのみ（`Auth::id()`）。他ユーザーのレビュー・書籍を含めない。
- 集計対象には論理削除済み（`deleted_at` が非NULL）の書籍に対する自分のレビューも含める。`Review::book()` リレーションには既存ルールにより `withTrashed()` スコープが適用済みのため、`Review::with('book')` で取得すれば削除済み書籍の情報も欠落しない。念のため、本走行の実装時に `Review::book()` の定義を確認し、`withTrashed()` が外れていないか確認すること。
- これはランキング画面（削除済み書籍を除外する）と意図的に異なる仕様である。ランキング側のロジック・スコープには一切手を加えない。

### 2-2. `$stats['summary']`

```php
$reviews = Review::where('user_id', Auth::id())->with('book.genres')->get();
$totalReviews = $reviews->count();
$booksRead = $reviews->pluck('book_id')->unique()->count();
$averageRating = $totalReviews > 0 ? round($reviews->avg('rating'), 1) : 0;
```

- `total_reviews`: 自分の全レビュー件数（重複投稿制限がないため、同一書籍への複数レビューもそれぞれ1件として数える）。
- `books_read`: 自分がレビューした書籍のユニーク数（`book_id` の重複を除いた数）。
- `average_rating`: 自分の全レビューのrating平均。レビュー0件のときは `0`（Bladeは `> 0` で分岐するのみで小数表示はしない）。

### 2-3. `$stats['rating_distribution']`

Collection型で返す（Bladeが `->max()` を呼ぶため、配列ではなくCollectionでなければならない）。要素数5、添字0が★1、添字4が★5に対応する。

```php
$ratingDistribution = collect(range(1, 5))
    ->mapWithKeys(fn (int $star): array => [
        $star - 1 => $reviews->where('rating', $star)->count(),
    ]);
```

### 2-4. `$stats['top_rated_books']`

自分がrating 4以上を付けた書籍を、書籍単位で評価の高い順に最大5件。各要素は `id` / `title` / `author` / `rating`（整数）を持つ。

**仕様上の注意（決定台帳D1参照）**: 同一書籍に複数レビューを投稿できる設計のため、1書籍に対して自分のレビューが複数存在し得る。この場合、その書籍の代表評価には自分がその書籍に付けた最高rating（`max`）を採用する。1件でも4以上のレビューがあれば「高評価書籍」として扱う。

```php
$topRatedBooks = $reviews
    ->filter(fn (Review $review): bool => $review->rating >= 4)
    ->groupBy('book_id')
    ->map(fn ($group): array => [
        'id' => $group->first()->book->id,
        'title' => $group->first()->book->title,
        'author' => $group->first()->book->author,
        'rating' => $group->max('rating'),
    ])
    ->sortByDesc('rating')
    ->take(5)
    ->values();
```

- 該当が1件もない場合は空のCollection（Bladeが「4星以上の書籍がありません」を表示する。コントローラー側で空チェックや文言出し分けはしない）。
- リンク先は書籍詳細（`books.show`）。この遷移はBlade側の実装であり、コントローラーは `id` を渡すのみでよい。

### 2-5. `$stats['genre_ratings']`

ジャンルごとに、自分のレビュー全体（`$reviews`）を対象として平均評価と件数を集計し、平均の高い順に最大5件。各要素は `id` / `name` / `count` / `average_rating` を持つ。

**仕様上の注意（決定台帳D9参照）**: 1冊の書籍が複数ジャンルに属する場合、その書籍へのレビューは該当する全てのジャンルの集計に計上する（多対多のジャンル紐付けをそのまま反映する。ジャンルを1つだけ代表として選ぶ処理はしない）。

- `average_rating` は丸めない生のfloat値をそのまま返す。表示側（`reports/index.blade.php`）が `number_format($genre['average_rating'], 1)` で小数第1位に整形する（Blade実装済み・変更禁止）。

```php
$genreRatings = $reviews
    ->flatMap(fn (Review $review) => $review->book->genres->map(fn (Genre $genre): array => [
        'id' => $genre->id,
        'name' => $genre->name,
        'rating' => $review->rating,
    ]))
    ->groupBy('id')
    ->map(fn ($group): array => [
        'id' => $group->first()['id'],
        'name' => $group->first()['name'],
        'count' => $group->count(),
        'average_rating' => $group->avg('rating'),
    ])
    ->sortByDesc('average_rating')
    ->take(5)
    ->values();
```

- 該当が1件もない場合は空のCollection（Bladeが「ジャンルが設定された書籍のレビューがありません」を表示する）。

### 2-6. ビューへの受け渡し

```php
return view('reports.index', ['stats' => [
    'summary' => [
        'total_reviews' => $totalReviews,
        'books_read' => $booksRead,
        'average_rating' => $averageRating,
    ],
    'rating_distribution' => $ratingDistribution,
    'top_rated_books' => $topRatedBooks,
    'genre_ratings' => $genreRatings,
]]);
```

`top_rated_books` と `genre_ratings` はBladeが `$book['id']` 形式（連想配列アクセス）で参照する実測契約のため、Collectionのまま渡してよい（Bladeの `@foreach` はCollectionでもそのまま動作し、各要素は配列として扱われる）。

## 3. シーディング（★BookSeeder・★ReviewSeeder）

### 3-1. `BookSeeder.php`

- 登録者を `User::first()` から `$users->random()->id` に変更する。
- 書籍タイトル・著者・ISBN・出版日・説明・画像URL・ジャンル紐付けは基本機能版と同一のまま変更しない。

### 3-2. `ReviewSeeder.php`

- 評価値の範囲を1〜5の全範囲に拡大する（基本機能版の3〜5から拡大）。
- コメントを評価別の日本語テンプレート5段階からランダムに選ぶ形にする。
  - 5: 「素晴らしい本でした！」「人生が変わりました。」「何度も読み返しています。」
  - 4: 「とても参考になりました。」「読みやすくておすすめです。」「期待通りの内容でした。」
  - 3: 「普通でした。」「可もなく不可もなく。」「期待したほどではなかった。」
  - 2: 「少し期待外れでした。」「内容が薄い印象。」「もう少し深掘りしてほしかった。」
  - 1: 「残念ながら合いませんでした。」「期待と違いました。」
- レビュー件数を書籍ごとに `rand(2, 4)` 件にする。
- 投稿者を `$users->random($reviewCount)` で選出する（同一書籍への重複投稿を禁止する制約はないため、同一ユーザーが同じ書籍に複数回選ばれても構わない）。
- `create` を使用する（既存のシーダーと同じ方式）。

### 3-3. 反映方法

シーダー変更は既存データを差し替えるため、実装完了後に `sail artisan migrate:fresh --seed` を実行し、全テーブルを再構築する。この結果、書籍の所有者（`user_id`）とレビュー内容は走行⑤確定時点から変わる（決定台帳D8参照。走行①〜⑥の検品済み内容には影響しない）。

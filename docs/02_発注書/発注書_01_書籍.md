# 発注書 01 書籍

書籍の一覧・検索・絞り込み・並び替え、詳細、登録、編集、削除（論理削除）、復元、ISBNからの自動入力、書籍の保存とジャンル紐付けのトランザクション、ISBN・出版日の任意入力を担当する。

- 合格の基準: `docs/03_検品表/01_書籍.md`（この番号の全条件を1条件1行で並べた表）。この発注書に書かれていても検品表に無い作業は完成条件に含まれない
- 共通の規則: `docs/共通ルール.md` の1章（着手前の確認・書かれていないことをしない・定義が無い場面での止まり方・変更してよい範囲・コミット・完了報告）と3章（文書の書き方）
- 提供モック・要件シート: 学校から配布された資料。提供モックは画面のひな形（Blade）、要件シートは作るものを定めた表で、所在と、実装との関係は `docs/00_提供資料/提供資料の所在.md` にある
- 全機能に共通する動き（未ログイン時の誘導・エラー画面・入力エラー時の戻り方・成功メッセージの表示規則・削除済み書籍の扱いの原則）: `docs/02_発注書/発注書_00_共通動作.md`
- 材料: 機能仕様書 1章（書籍）・0章、全体仕様書 3章（PG01〜PG04）・4章（ルート一覧）・5章（権限一覧）・11章（`books` のテーブル定義）、技術決定書 TD-01・TD-02・TD-04・TD-10〜TD-17・TD-22・TD-31〜TD-33

## 4. 作るもの

### 4-1. 書籍一覧（PG01）

| 項目 | 確定値 |
|---|---|
| URL | `GET /` と `GET /books` が同じ画面を返す |
| 表示件数 | 1ページ10件。ページ送りのリンクに検索条件（`keyword`・`genre`・`sort`）を引き継ぐ |
| 対象 | 削除済みの書籍を除く |
| キーワード `keyword` | タイトルまたは著者名の部分一致。前後の空白を除いてから使う |
| ジャンル `genre` | 指定したジャンルIDの書籍に絞る。`0` と未指定は絞らない |
| 並び順 `sort` | `newest` 新しい順（既定）／ `oldest` 古い順／ `title` タイトル順／ `rating` 評価が高い順（レビュー平均の降順）。それ以外の値は新しい順 |
| 入力チェック | 検索条件には入力ルールを置かず、不正な値でもエラーにしない |
| 検索フォーム | キーワード欄（placeholder「タイトル・著者で検索」）、ジャンルのプルダウン（先頭が「すべて」、続いて全ジャンル）、並び順のプルダウン（「評価が高い順」をタイトル順の後ろに置く）、「検索」「リセット」ボタン、「書籍を登録」ボタン |
| 出さないもの | 「検索結果: N件」の件数表示、各書籍の★評価、error のフラッシュ表示 |
| 0件のとき | 「書籍が見つかりませんでした。」（検索して0件のときも、書籍が1冊も無いときも同じ） |
| 画像が無いとき | 「画像なし」 |
| フラッシュ | 書籍削除後の「書籍を削除しました」をここに出す |

### 4-2. 書籍詳細（PG02）

| 項目 | 確定値 |
|---|---|
| 権限 | 不要。削除済みの書籍も表示する |
| 表示 | タイトル、画像（無ければ「画像なし」）、著者、ISBN（無ければ「未登録」）、出版日（無ければ「未登録」）、ジャンル、説明（ある場合のみ） |
| 編集・削除ボタン | 登録者本人かつ削除されていない書籍のときだけ出す。削除は「本当に削除しますか？」の確認を出す |
| 復元ボタン「復元する」 | 登録者本人かつ削除済みの書籍のときだけ出す |
| 削除済みの表示 | 上部に「この本は削除されました」 |
| お気に入りボタン | 削除されていない書籍のときだけ出す（ボタンの動きは 04 の担当） |
| レビュー投稿フォームの代わりの文言 | 未ログインは「レビューを投稿するにはログインしてください。」、削除済みの書籍は「削除済みの書籍にはレビューを投稿できません」 |
| フラッシュ | 書籍の登録・更新・復元の完了メッセージをここに出す |

### 4-3. 書籍登録（PG03）

| 項目 | 確定値 |
|---|---|
| 画面 | ジャンルを全件、ID の小さい順にチェックボックスで並べる |
| 登録者 | ログイン中の会員（`books.user_id`） |
| 保存 | 書籍の保存とジャンルの紐付け（`book_genre`）を `App\Http\Controllers\BookController@store` の中で1つのトランザクション（`DB::transaction`）にまとめる |
| 成功時 | 登録した書籍の詳細画面 `/books/{book}` へ移動し、「書籍を登録しました」 |
| 失敗時 | 入力画面に戻り、各項目の下にエラー文言を出す |

### 4-4. 入力ルール（登録・更新共通）

`App\Http\Requests\StoreBookRequest` と `App\Http\Requests\UpdateBookRequest` に、ルールと文言を同じクラスに書く。更新では ISBN の重複チェックから自分自身を除く。

| 項目 | ルール | エラー文言 |
|---|---|---|
| タイトル `title` | 必須・文字列・255文字以内 | 「タイトルを入力してください」「タイトルは255文字以内で入力してください」 |
| 著者 `author` | 必須・文字列・255文字以内 | 「著者名を入力してください」「著者名は255文字以内で入力してください」 |
| ISBN `isbn` | 任意・文字列・数字13桁・未登録（削除済みの書籍の ISBN とも重複不可） | 「ISBNは13桁の数字で入力してください（入力がある場合のみ）」「このISBNは既に登録されています」 |
| 出版日 `published_date` | 任意・日付 | 「出版日は正しい日付形式で入力してください（入力がある場合のみ）」 |
| 説明 `description` | 任意・文字列・1000文字以内 | 「説明は1000文字以内で入力してください」 |
| 画像URL `image_url` | 任意・URL形式・255文字以内 | 「画像URLの形式が正しくありません」「画像URLは255文字以内で入力してください」 |
| ジャンル `genres` | 必須・配列・1つ以上。各IDが存在すること | 「ジャンルを1つ以上選択してください」「選択されたジャンルが存在しません」 |

- ISBN と出版日を空で送ったときは、`books.isbn`・`books.published_date` を NULL で保存する
- 文字列・配列のルールには個別の文言を置かず、`lang/ja/validation.php` の共通の文言を使う

### 4-5. 出版日の型

`App\Models\Book` で `published_date` を日付型（`date`）に変換する。読み出した値は `Illuminate\Support\Carbon` になる。

### 4-6. ISBNからの自動入力（登録画面のみ）

画面（`resources/views/books/create.blade.php`）

| 項目 | 確定値 |
|---|---|
| 置き場所 | 登録画面の上部。編集画面には置かない |
| 見出し | 「📖 ISBN から書籍情報を自動入力」 |
| 入力欄・ボタン | 入力欄の id は `isbn_search`、ボタンの id は `isbn_search_button`、ボタンの文字は「🔍 検索」 |
| 動き | ボタンを押すと画面を移動せずに `GET /books/isbn/{isbn}` を呼び、返ってきた値をフォームの各入力欄へ入れる。13桁の事前チェックは画面側でせず、サーバーの判定に任せる |
| 成功の表示 | 「書籍情報を自動入力しました」 |
| 出版日を補ったときの表示 | 「出版日は年月までの情報のため、日付は仮の値（1日）を自動設定しました。正しい日付が分かる場合は修正してください。」 |
| 失敗の表示 | 返ってきた `message` を赤字で出す。`message` が無ければ「書籍情報の取得に失敗しました」 |

処理（`App\Http\Controllers\BookController@searchByIsbn`）

| 項目 | 確定値 |
|---|---|
| 13桁の確認 | コントローラーの中で確かめる（FormRequest を作らない）。13桁の数字でなければ 422 `{"message": "ISBNは13桁の数字で入力してください"}` |
| 呼び出し先 | Google Books API。時間制限5秒（`timeout(5)`） |
| APIキー | `config/services.php` に Google Books API のキーの項目を置き、値を `.env` から読む。値があるときだけ `key` を付けて呼ぶ |
| 返す内容 | `title`、`author`（著者が複数なら「、」でつなぐ）、`description`、`image_url`（サムネイル）、`published_date`、`published_date_padded` |
| 出版日の補正 | 年のみ（`2012`）は `2012-01-01`、年月のみ（`2012-06`）は `2012-06-01` にして `published_date_padded` を true。年月日はそのままで false。それ以外の形式は空 |
| 該当なし | 404 `{"message": "該当する書籍が見つかりませんでした"}` |
| 通信失敗・API側のエラー | 502 `{"message": "書籍情報の取得に失敗しました"}` |

### 4-7. 書籍編集（PG04）

| 項目 | 確定値 |
|---|---|
| 権限 | 登録者本人のみ。削除済みの書籍は404 |
| 入力欄 | `resources/views/books/_form.blade.php` を使う。登録済みの値を初期値にし、出版日は「年-月-日」に整えて入れる（時刻付きの文字を入れると日付の入力欄が空欄になるため） |
| 入力ルール | 4-4 と同じ。ISBN の重複チェックから自分自身を除く |
| 成功時 | 書籍の詳細画面へ移動し、「書籍を更新しました」 |
| 本人以外 | 403 |

### 4-8. 削除（論理削除）と復元

| 項目 | 確定値 |
|---|---|
| 削除 | 登録者本人のみ。`books.deleted_at` に日時を入れる論理削除。レビュー・お気に入り・ジャンルの紐付け・読書計画は残す |
| 削除の成功時 | 書籍一覧 `/books` へ移動し、「書籍を削除しました」 |
| 復元 | 登録者本人かつ削除済みの書籍のみ。`books.deleted_at` を NULL に戻す |
| 復元の成功時 | 書籍の詳細画面へ移動し、「書籍を復元しました」 |
| 権限が無い | 403（本人以外の削除・復元、削除されていない書籍の復元） |

`App\Models\Book` は `SoftDeletes` を使う。物理削除の処理を作らない。

### 4-9. 権限判定（`App\Policies\BookPolicy`）

| メソッド | 許可する条件 |
|---|---|
| `update` | 登録者本人で、かつ削除されていない |
| `delete` | 登録者本人で、かつ削除されていない |
| `restore` | 登録者本人で、かつ削除済み |

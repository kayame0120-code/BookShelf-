## 4. テストのカテゴリ

テストのカテゴリは、各機能の動きを確かめるものと、「画面要素の描画」の2種類に分ける。

「画面要素の描画」は、書籍一覧の検索フォーム（キーワード欄 `name="keyword"`・ジャンル・並び順と、検索・リセット・書籍を登録のボタン）と、書籍登録画面の ISBN 自動入力の枠（`isbn_search`・`isbn_search_button`）が、要件シートのデザインどおりに画面に出ているかを確かめるテストである。動きのカテゴリのどれにも当てはまらないため、独立させる。カテゴリはファイルごとに1つ決める。

## 5. テストファイルと機能軸の対応一覧

実在するテストファイルはすべてこの表に載せ、この表には実在するファイルだけを載せる。ファイルは `tests/` からのパスで書く。機能軸は 00〜12 の番号で書き、1つのファイルが複数の機能軸を確かめる場合は「・」でつなぐ。

機能軸の決め方:

- テストが呼ぶURI・Artisan コマンド・Enum を、それを担当する番号に割り当てる（例: `reading-plans:expire` と `reading-plans:send-reminders` は、状態を変える処理を含めて 09）
- モデル間の関連（`belongsTo`・`hasMany`・`belongsToMany`）だけを確かめるテストは、関連の定義を持つ 11 に割り当てる
- `App\Models\Review::book` が削除済みの書籍も取れること（`withTrashed`）は、削除済み書籍の扱いの原則を持つ 00 に割り当てる

## 6. コード品質

| 項目 | 確定値 |
|---|---|
| 整形 | `sail bin pint --test` の指摘が0件 |
| 型宣言 | `App\Models\User`・`App\Models\Genre`・`App\Models\Book`・`App\Models\Review`・`App\Models\ReadingPlan` のクラスに書かれたメソッドすべてに、戻り値の型宣言を付ける |
| PHPDoc | 同じ5本のクラスに書かれたメソッドすべてに、PHPDoc を付ける |
| 命名規則 | `app/Http/Controllers/` のクラス名は `Controller`、`app/Http/Requests/` は `Request`、`app/Policies/` は `Policy` で終える |
| 入力チェックの分離 | 入力チェックは FormRequest に書き、コントローラーに `->validate(`・`Validator::make` を書かない。例外は ISBN 検索の13桁の確認（`App\Http\Controllers\BookController@searchByIsbn`）で、確かめる値がURLの1つだけで、エラーを表示する画面も無いため、コントローラーで行う。会員登録の入力チェックは Fortify の `App\Actions\Fortify\CreateNewUser` に書く |

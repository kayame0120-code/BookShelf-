## 3. `ReadingPlanReminder` 通知クラス

```php
class ReadingPlanReminder extends Notification
{
    public function __construct(
        private readonly ReadingPlan $plan,
        private readonly NotificationTiming $timing,
    ) {
    }

    public function via(object $notifiable): array
    {
        return ['database'];
    }

    public function toDatabase(object $notifiable): array
    {
        return [
            'timing' => $this->timing->value,
            'title' => $this->title(),
            'body' => $this->body(),
            'reading_plan_id' => $this->plan->id,
        ];
    }

    private function title(): string
    {
        return match ($this->timing) {
            NotificationTiming::ThreeDaysBefore => '読書計画のリマインダー',
            NotificationTiming::OnDueDate => '読書計画の期日です',
            NotificationTiming::ThreeDaysAfter => '読書計画の期日が過ぎました',
        };
    }

    private function body(): string
    {
        $title = $this->plan->book->title;

        return match ($this->timing) {
            NotificationTiming::ThreeDaysBefore => "『{$title}』の期日まで残り3日です。",
            NotificationTiming::OnDueDate => "『{$title}』の期日は本日です。",
            NotificationTiming::ThreeDaysAfter => "『{$title}』の期日から3日が経過したため、計画は自動的に「期限切れ」になりました。",
        };
    }
}
```

文言は要件シートの確定文言をそのまま使用する。

## 4. リマインダーバッチ（7:00）

**決定台帳D3参照**: コマンドクラス名は `SendReadingPlanReminders`（シグネチャ `reading-plans:send-reminders`）とする。

### timing別の対象status（確定）

3つのtimingは、対象とする計画のstatusが異なる。この違いは0:00の自動失効バッチ（`reading-plans:expire`）との実行順序に起因する確定仕様であり、実装で必ず守る。

| timing | 対象status | 理由 |
|---|---|---|
| `three_days_before`（期日3日前） | `in_progress` のみ | 期日前の計画は必ず進行中であり、失効の対象になっていない。 |
| `on_due_date`（期日当日） | `in_progress` のみ | 期日当日の計画はまだ失効していない（失効は期日を3日過ぎてから）。 |
| `three_days_after`（期日3日後） | `in_progress` ＋ `expired` | 本バッチ（7:00）の実行時点では、0:00の自動失効バッチによって当該計画が既に `expired` へ切り替わっている。対象を `in_progress` のみに絞ると「期限切れになりました」通知が誰にも作成されず漏れる。したがって `completed` 以外（`in_progress` と `expired`）を対象とする。 |

### 実装

```php
class SendReadingPlanReminders extends Command
{
    protected $signature = 'reading-plans:send-reminders';

    protected $description = '進行中の読書計画に対し、期日の3日前・当日・3日後のリマインダー通知を送信する';

    public function handle(): int
    {
        $today = Carbon::today();

        // timing 別の対象 status。three_days_after のみ completed 以外
        // （in_progress ＋ expired）を対象とする。0:00 の自動失効バッチで
        // 既に expired へ切り替わった計画にも「期限切れ」通知を届けるため。
        $this->notify(
            $today->copy()->addDays(3),
            NotificationTiming::ThreeDaysBefore,
            [ReadingPlanStatus::InProgress],
        );
        $this->notify(
            $today->copy(),
            NotificationTiming::OnDueDate,
            [ReadingPlanStatus::InProgress],
        );
        $this->notify(
            $today->copy()->subDays(3),
            NotificationTiming::ThreeDaysAfter,
            [ReadingPlanStatus::InProgress, ReadingPlanStatus::Expired],
        );

        return self::SUCCESS;
    }

    /**
     * 指定日を期日とする対象statusの計画の所有者へ通知を送る。
     *
     * @param  array<int, ReadingPlanStatus>  $statuses
     */
    private function notify(Carbon $targetDate, NotificationTiming $timing, array $statuses): void
    {
        ReadingPlan::whereIn('status', $statuses)
            ->whereDate('target_date', $targetDate)
            ->with('user')
            ->get()
            ->each(function (ReadingPlan $plan) use ($timing): void {
                try {
                    $plan->user->notify(new ReadingPlanReminder($plan, $timing));
                } catch (\Throwable $e) {
                    Log::error("読書計画#{$plan->id}の通知送信に失敗しました: {$e->getMessage()}");
                }
            });
    }
}
```

判定基準:

- 対象は §4「timing別の対象status（確定）」の通り。`three_days_before`・`on_due_date` は `in_progress` のみ、`three_days_after` は `in_progress` ＋ `expired`。いずれの timing でも `completed` の計画は対象外。
- `target_date` は各 timing に対応する日（「本日+3日」「本日」「本日-3日」）に `whereDate` で一致するもの。
- 通知の `notifiable_id` は計画の所有者。他ユーザーには届かない。
- 対象外の日付（例: 本日+7日）には通知が作成されない。
- 対象0件でも異常終了しない。
- 個別失敗時はログに記録し、他レコードの処理は継続する。

`routes/console.php`（またはコンソールカーネル）に以下を登録する。

```php
Schedule::command('reading-plans:send-reminders')->dailyAt('07:00');
```

0:00の `reading-plans:expire`（発注書11で登録済み）とは別のスケジュールとして登録すること（同一コマンドに統合しない）。

## 5. `NotificationController`

```php
Route::get('/notifications', [NotificationController::class, 'index'])->name('notifications.index');
Route::post('/notifications/{notification}/read', [NotificationController::class, 'read'])->name('notifications.read');
```

- `index`: `Auth::user()->notifications` を新しい順に取得して `$notifications` として渡す。
- `read`: 対象通知の `notifiable_id` が `Auth::id()` と一致するか確認する（一致しなければ403）。一致すれば `markAsRead()` を呼ぶ。成功時は `back()`（元画面のまま）、flashは表示しない（未読バッジが消えることで状態を表現する。既存のトグル系操作とflash方針を統一する）。

認可はPolicyクラスを新設せず、コントローラー内で `notifiable_id` の一致チェックのみで実装する。

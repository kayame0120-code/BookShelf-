# 提供資料の所在

このアプリは、学校から配布された2つの資料をもとに作られている。Bladeモックと要件シートである。この文書は、その2つがどこにあり、このアプリとどういう関係にあるかを案内する。資料の実体はここに置かない。

---

## 1. Bladeモック

画面の見た目と構造をあらかじめ用意したBladeテンプレート一式。このアプリの画面は、これを取り込んで作った。

### 取得先

```
https://github.com/coachtech-prepared-file/Preparedblade-mockcase-BookShelf.git
```

ブランチが2つある。どちらも配布された時点の内容から変更しない。

| ブランチ | 収録されている画面 |
|---|---|
| `basic` | 書籍・ジャンル・レビュー・いいね・お気に入り・ランキング・会員登録・ログイン |
| `advanced` | 上に加えて、マイ読書レポート・読書計画・通知・ヘッダー |

### 取得するコマンド

```bash
git clone --depth 1 -b basic https://github.com/coachtech-prepared-file/Preparedblade-mockcase-BookShelf.git blade-basic
git clone --depth 1 -b advanced https://github.com/coachtech-prepared-file/Preparedblade-mockcase-BookShelf.git blade-advanced
```

`--depth 1` は最新の状態だけを取ってくる指定で、過去の履歴はダウンロードしない。取り込みは済んでいるため、これを実行するのは、このアプリの画面と配布時の画面を見比べたいときだけである。

## 2. 要件シート

学校から配布されたExcelのファイル。作るものの一覧、画面の設計、入力チェックの文言、初期データの内容、テストの観点、テーブルの仕様、APIの仕様が入っている。

このリポジトリには置いていない。配布物として制作者が手元に保持しており、完成した内容は学校が指定したスプレッドシートへ反映して提出する。

リポジトリに置かない理由は、Excelのファイルが差分を追えない形式で、更新のたびにリポジトリの容量を増やすためである。内容のうちこのアプリの姿を説明する部分は、`docs/01_仕様書/` の3本にすべて書き起こしてある。

---

## 3. 提供資料と実装が食い違うときの扱い

### 今のアプリの姿は実装である

このアプリが何をどう動かしているかを知りたいときは、`docs/01_仕様書/` の3本を見る。3本は実装コードから書き起こしたものであり、提供資料から書いたものではない。

提供資料と実装が食い違う箇所がある場合、実装のほうが現在の姿である。提供資料は出発点であって、現在の姿の記録ではない。

食い違いが生まれた理由は2つある。

1. 配布された資料どうしが食い違っていた箇所があり、そのつど片方を選んだ
2. 画面のデザインに関する指定を優先して、モックの記述と違う形にした箇所がある

どの箇所をなぜそうしたかは、`docs/01_仕様書/技術決定書.md` に理由つきで書いてある。

### 作っている最中は逆だった

実装を進めている最中は、資料どうしが食い違ったときにBladeモックを優先する規則で進めた。この規則は `CLAUDE.md` に書かれており、実装を行うAIに今もかかっている。

2つの規則は反対のことを言っているように見えるが、対象が違う。

| 規則 | いつの話か | 何を決めるか |
|---|---|---|
| Bladeモックを優先する | これから画面を作る・直すとき | 資料が食い違ったとき、どちらに合わせて作るか |
| 実装が現在の姿である | 今のアプリを説明するとき | このアプリが何をしているかを、どこを見て答えるか |

画面を直す作業が発生したときは前者に従い、このアプリの動きを説明するときは後者に従う。
